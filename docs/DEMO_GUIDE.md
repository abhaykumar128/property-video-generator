# PropertyStudio AI — Demo Guide

A walkthrough plan for recording a short screen demonstration of the
AI Property Video Generator.

Target length: 3–5 minutes.

---

## 1. Introduction (30 seconds)

**What to say:**

> Real estate agents spend hours editing promotional videos for property
> listings. PropertyStudio AI automates this — you enter property details,
> upload photos, and the app generates a professional vertical MP4 in seconds.
>
> The app uses Google Gemini AI for script generation with a template fallback,
> Sharp for image processing, and FFmpeg for real video rendering.

**What to show:**

- The PropertyStudio AI landing page at `http://localhost:5173`
- The 5-step progress indicator at the top

---

## 2. Property Form Walkthrough (45 seconds)

**What to do:**

1. Click **"Load Sample Data"** button (top-right of the form)
2. The form auto-fills with synthetic property data:
   - Property name: Sunrise Residency
   - Location: Mohali, Punjab
   - Price: ₹85 lakh
   - Type: 2-BHK Apartment
   - Features: Two spacious bedrooms, Private balcony, Covered parking, Modular kitchen
   - Agent: Priya Sharma, +91 98765 43210
3. Point out the validation — try clearing the property name and see the error
4. Click **"Next: Upload Images →"**

**What to explain:**

> The form validates all required fields client-side and the backend uses Zod
> for server-side validation. All data is synthetic — no real customer information.

---

## 3. Uploading Sample Images (45 seconds)

**What to do:**

1. On the image upload page, show the drag-and-drop zone
2. Drag the 6 sample images from `samples/sample-images/` into the browser
   (or click to browse and select them)
3. Show the thumbnail grid — each image has a number badge showing scene order
4. Demonstrate reordering: drag one thumbnail to a different position
5. Show the count bar at the bottom — it fills as you add images
6. Explain the 4–8 image requirement
7. Try removing an image with the ✕ button
8. Click **"Next: Generate Script →"**

**What to explain:**

> The app requires 4–8 images. You can reorder them by dragging — the order
> determines the scene sequence in the video. Accepted formats are JPEG, PNG,
> and WebP, with a 10 MB per-image limit.

---

## 4. Generating and Reviewing Captions (45 seconds)

**What to do:**

1. The app automatically calls the script generation API
2. Show the loading spinner while it generates
3. The script appears with:
   - Opening title (property name + location)
   - Scene captions (one per image, from features)
   - Call to action (agent name + phone)
4. Point out the badge: "Template-based" or "AI-generated"
5. Demonstrate editing — click on a caption and change the text
6. Show the collapsible voice-over summary
7. Click **"Next: Generate Video →"**

**What to explain:**

> The script is generated by Google Gemini AI if an API key is configured,
> otherwise a deterministic template is used. The template never invents facts
> — it only uses the property details you supplied. You can edit any caption
> before the video is rendered.

---

## 5. Creating the Video (60 seconds)

**What to do:**

1. Show the summary card (property, images, script, format)
2. Click **"Generate Video"**
3. Watch the progress messages:
   - "Uploading images and property details…"
   - "Job accepted. Starting render…"
   - "Generating promotional script…"
   - "Images ready. Rendering video…"
4. Wait for the render to complete (~20–40 seconds)

**What to explain:**

> The backend runs the pipeline asynchronously — it generates the script,
> uses Sharp to resize images and add text overlays, then uses FFmpeg to
> assemble the frames into an MP4 with crossfade transitions. The frontend
> polls the job status every 3 seconds. FFmpeg is bundled via npm — no
> manual installation needed.

---

## 6. Previewing and Downloading (30 seconds)

**What to do:**

1. The video player loads automatically
2. Use the playback controls to preview the video
3. Point out the vertical 9:16 format (1080×1920)
4. Click **"Download MP4"** — the file saves to your downloads folder
5. Show the file in the downloads — it's a real H.264 MP4
6. Click **"Create Another Video"** to return to step 1

**What to explain:**

> The video is a real H.264 MP4 — about 21 seconds, 1080×1920, 30fps.
> You can download it directly. The stream endpoint supports HTTP range
> requests for smooth browser playback.

---

## 7. Demonstrating an Error Case (30 seconds)

**What to do:**

1. Go back to Step 2 (image upload)
2. Remove images until fewer than 4 remain
3. Try clicking "Next" — the button is disabled
4. Add a text file instead of an image — show the error message
5. Go to Step 1 and clear a required field — show the validation error

**What to explain:**

> The app validates inputs at multiple levels — client-side form validation,
> server-side Zod schema validation, Multer file type and size checks, and
> FFmpeg error handling. Error messages are user-friendly and never expose
> internal paths, stack traces, or API keys.

---

## 8. Gemini Integration and Template Fallback (20 seconds)

**What to say:**

> The Gemini API generates promotional copy from the property facts. The prompt
> explicitly instructs the model not to invent amenities. If the API key is
> missing or the request fails, the app falls back to a deterministic template
> that uses only the supplied data. The source is always shown to the user.

---

## 9. How FFmpeg Renders the Video (20 seconds)

**What to say:**

> FFmpeg is called via the fluent-ffmpeg library — never through raw shell
> commands. Each image is resized to 1080×1920 with Sharp, then an SVG text
> overlay is composited on top. FFmpeg chains the PNG frames with xfade
> crossfade transitions, encodes to H.264, and adds the moov atom at the
> start for fast web streaming. The output is verified — file must exist
> and be non-empty before the job is marked complete.

---

## 10. Key Implementation Decisions (20 seconds)

**What to say:**

> - **FFmpeg bundled** via ffmpeg-static — no system installation required
> - **Template fallback** — the app works fully without a Gemini API key
> - **Async job processing** — video rendering never blocks the HTTP request
> - **UUID job IDs** — safe filenames, no user input in filesystem paths
> - **9:16 vertical** — optimised for mobile and social media platforms
> - **In-memory job store** — simple for demo scope, no database needed

---

## 11. Known Limitations (15 seconds)

**What to say:**

> Jobs are in-memory and lost on restart. The video is silent unless you
> upload an audio file. There's no authentication — this is a demo app.
> Future improvements include database persistence, background music,
> text-to-speech voiceover, and landscape format support.

## Pre-Demo Checklist

Before recording:

- [ ] Backend running (`cd backend && npm run dev`)
- [ ] Frontend running (`cd frontend && npm run dev`)
- [ ] Browser open at `http://localhost:5173`
- [ ] Sample images available in `samples/sample-images/`
- [ ] Sample MP4 verified at `samples/output/sample-property-video.mp4`
- [ ] Screen recording software ready
- [ ] Both terminal windows visible (optional — to show backend logs)

## Post-Demo Checklist

After recording:

- [ ] Verify the downloaded MP4 plays in a media player
- [ ] Confirm the video is 1080×1920, ~21 seconds, H.264
- [ ] Check that no API keys or secrets appeared in the recording
